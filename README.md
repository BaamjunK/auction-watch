# auction-watch — 아파트 경매 권리분석 대시보드

법원경매정보(courtauction.go.kr)에 올라온 **아파트** 경매 물건 중
**300세대 이상 · 유찰 2회 미만** 조건을 통과한 물건을 자동 수집하고,
공개 자료(매각물건명세서 요약·현황조사서)를 근거로 **AI 권리분석**을 수행해
정적 웹 대시보드(`docs/index.html`)에 등록한다.

```
법원경매 검색 API ──▶ 아파트/유찰/지역 필터 ──▶ 세대수 필터(네이버 부동산) ──▶ 물건상세+현황조사 수집
                                                                                │
docs/index.html ◀── 대시보드 생성 ◀── 권리분석 에이전트(claude CLI 헤드리스) ◀──┘
```

## 구성 요소

| 파일 | 역할 |
|---|---|
| `auctionwatch/courtauction.py` | 법원경매정보 비공식 JSON API 클라이언트 (검색/물건상세/현황조사서) |
| `auctionwatch/naver.py` | 네이버 부동산으로 단지 세대수 조회 — **API 키 불필요** (기본 경로, 캐시) |
| `auctionwatch/kapt.py` | 공공데이터포털 K-apt API 세대수 조회 — 네이버 매칭 실패 시 보조 (키 있을 때만) |
| `auctionwatch/checks.py` | 권리 자동 체크리스트 — 결정적 룰 엔진(LLM 무관, 재현 가능) |
| `auctionwatch/analyzer.py` | `claude -p` 헤드리스 호출 경매 전문가 에이전트 → JSON 판정 + 등급 |
| `auctionwatch/webgen.py` | 데이터 인라인 단일 HTML 대시보드 생성 (file:// 로 열어도 동작) |
| `auctionwatch/pipeline.py` | 전체 오케스트레이션 + `data/state.json` 상태 관리 |

### 전문가 에이전트의 역할

물건마다 아래를 분석해 대시보드 카드에 등록한다.

| # | 역할 | 산출물 |
|---|---|---|
| 1 | **권리 분석** | 말소기준권리 판단, 낙찰자 인수 권리, 대항력 임차인 여부 → 판정(안전/주의/위험) + 권리점수 |
| 2 | **권리 자동 체크리스트** | 유치권·전세권·임차권등기·대지권·별도등기·지분·재매각·전입일 대비 대항력을 코드로 기계 판정 (`checks.py`, LLM 무관) |
| 3 | **법률 분석** | 쟁점별 관련 법령·판례 법리 (주임법 대항력·우선변제, 민사집행법 인도명령/무잉여, 집합건물법 대지사용권 등) |
| 4 | **가격 분석** | 감정가·최저가를 네이버 단지 호가 밴드와 비교한 시세 대비 평가 |
| 5 | **입지 분석** | 역세권·학군·상권 각 10점 (AI 지역지식 기반) |
| 6 | **입찰 가이드** | 매각기일/법정, 입찰보증금(특별매각조건이면 20% 명시), 준비물, 물건별 유의사항 |
| 7 | **사후 처리(명도)** | 점유자 유형별 인도명령 가능 여부, 절차 순서, 예상 기간, 협상 포인트 |
| 8 | **종합 판별표** | S/A/B/C/D 등급 + 한 줄 판단 — 카드 최상단에 표시, 대시보드 정렬 기준 |

⚠️ **대리 입찰은 수행하지 않는다.** 매수신청대리는 공인중개사·변호사 등록이
필요한 법률 행위이므로 절차 가이드까지만 제공한다.

### 대시보드에 함께 담긴 것

- **경매 참석 절차 가이드** — 상단 접이식 패널. 입찰 전 준비(등기부·전입세대열람·임장·자금),
  당일 실무(준비물, 마감 시각, 기일입찰표 작성, 흔한 무효 사유), 낙찰 후(허가결정 →
  대금납부 → 취득세 60일 → 인도명령 6개월 → 배당)를 단계별로 정리
- **초보자용 용어 풀이** — 39개 경매 용어 사전(접이식) + 본문 자동 툴팁. 카드 본문의
  전문 용어에 점선 밑줄이 붙고 누르면 쉬운 말 설명이 뜬다. 등급(S~D)과 판정(안전/주의/위험)
  옆에도 "낙찰가 외에 더 물어줄 돈이 없어 보입니다" 같은 해설을 함께 표시
- **지도 연동** — 카드마다 네이버지도·카카오맵·구글맵·네이버 부동산·실거래가 검색 링크.
  API 키가 필요 없다. 지도 앱은 지번보다 **단지명으로 훨씬 정확하게 찾으므로**
  단지명이 확인된 물건은 `동이름 + 단지명`(예: `목동 목동신시가지7단지`)으로,
  확인되지 않은 물건만 지번 주소로 검색한다. 네이버 부동산 링크는 단지 ID가
  확인된 경우에만 노출해 엉뚱한 검색 결과로 보내지 않는다

### 수익률 계산기 (대시보드 내장, 클라이언트 계산)

카드마다 입력값(입찰가·매도가·대출비율·금리·보유기간·수리비·명도비·보유주택수)을
조정해 즉시 재계산한다.

- **세금 자동계산** — 취득세(6억↓ 1% / 6~9억 선형 / 9억↑ 3%, 다주택 8% 중과)
  + 지방교육세 + 농어촌특별세(85㎡ 초과) 세목별 표, 보유세 근사, 양도소득세
  근사(보유기간별 77%/66%/44%, 지방소득세 포함)
- **시나리오 3개** — 보수(매도가 −7%·수리비 1.5배·보유 +6개월) / 기준 / 공격(+7%)
  각각 총비용·세후이익·자기자본수익률
- **역산 입찰가** — 목표 자기자본수익률을 입력하면 이분탐색으로 상한 입찰가를
  계산하고, 최저매각가와 비교해 "이번 기일 가능/유찰 대기 필요"를 판정

세율·비용은 단순화 가정이다(기본공제·장기보유특별공제 미반영). 실제 세액은
세무사 확인이 필요하며, 계산기 하단에 가정을 명시해 두었다.

### 세대수 조회

기본은 **네이버 부동산**(키 불필요)이며 3단계로 시도한다.

1. **단지명 매칭** — 소재지의 시도/시군구/동을 네이버 지역 트리 API로 법정동코드로
   해석한 뒤, `cluster/ajax/complexList?cortarNo={법정동코드}` 로 그 동의 전체
   아파트 단지 목록(단지명·총세대수·호가)을 받아 정규화 매칭. 재건축 추진 단지
   (JGC 분류)도 함께 조회하고, 동 이름 표기 차이를 보정한다
   ('행당동대림아파트' ↔ '행당대림')
2. **지번 대조** — 후보 단지의 상세 페이지에서 `address.jibun` 을 읽어 물건 지번과
   비교. 지도앱에서 주소로 확인하는 것과 같은 방식이라, 단지명 표기가 전혀 달라도
   주소가 같으면 잡힌다. 분당·뉴타운처럼 소재지에 마을명만 있는 물건이 여기서
   해결된다 ('한솔마을 205동' → 한솔2단지LG 598세대, '이매촌아파트' → 이매진흥 828세대).
   요청을 줄이려고 마을명 어간이 겹치는 후보를 먼저 조회하고, 결과는 캐시한다
3. **키워드 검색** — 위 둘이 실패하면 `search/result/{동 단지명}` 리다이렉트로 재시도

법정동 범위 안에서만 매칭하고, 지번은 **완전 일치**만 인정한다(부번이 다르면 인접
필지의 다른 단지일 수 있어 배제 — 실제로 구의동 587-58 물건이 587-54 단지로 잡히던
오매칭을 이 규칙으로 막았다). 그래도 확인이 안 되는 경우는 "세대수 미확인" 보류로
남긴다 — 단지명이 없는 나홀로 아파트, 도로명 주소만 있어 지번을 못 얻는 물건 등.
**세대수·면적·가격 기준 미달로 확인된 물건은 대시보드에 표시하지 않는다.**

미확인을 더 줄이고 싶으면 **선택적으로** K-apt API 키를 등록하면
지번주소 매칭으로 보조 조회한다:

1. [공공데이터포털](https://www.data.go.kr)에서 **공동주택 단지 목록제공 서비스**(AptListService3),
   **공동주택 기본 정보제공 서비스**(AptBasisInfoServiceV3) 활용신청 (무료, 자동승인)
2. 인증키를 `config.json` 의 `kapt.service_key` 또는 환경변수 `KAPT_SERVICE_KEY` 에 설정

## 실행

```bash
# 수집 + 필터만 (claude 호출 없이 빠르게 확인)
python3 -m auctionwatch.pipeline --no-analyze

# 전체 파이프라인 (권리분석 포함)
python3 -m auctionwatch.pipeline

# 테스트: 상위 5건만
python3 -m auctionwatch.pipeline --limit 5
```

실행 후 `docs/index.html` 을 브라우저로 열면 대시보드가 보인다.

```bash
open docs/index.html
```

## 자동 실행 (launchd, 매일 09:00 / 15:00)

```bash
sed -e "s|__PROJECT_DIR__|$PWD|g" -e "s|__HOME__|$HOME|g" \
  launchd/com.auction-watch.plist > ~/Library/LaunchAgents/com.auction-watch.plist
launchctl load ~/Library/LaunchAgents/com.auction-watch.plist
```

plist 안의 `__PROJECT_DIR__`·`__HOME__` 은 설치할 때 치환한다. `PATH` 에
`~/.local/bin`(claude CLI)과 `/opt/homebrew/bin`(gh)이 들어가야 하며, `deploy.sh`
는 requests 가 설치된 python3 를 직접 골라 쓴다 — launchd 의 PATH 에서는 다른
python3 가 먼저 잡힐 수 있기 때문이다.

해제:

```bash
launchctl unload ~/Library/LaunchAgents/com.auction-watch.plist
```

로그: `data/launchd.log`

## 설정 (config.json)

| 키 | 기본값 | 설명 |
|---|---|---|
| `filters.min_households` | 300 | 최소 세대수. 0이면 세대수 필터 비활성화 |
| `filters.min_area_m2` | 59 | 최소 전용면적(㎡). 법원 검색 API 서버측 필터 + 로컬 재확인 |
| `filters.min_bid_price` | 0 | 최저매각가 하한(원). 0이면 비활성 |
| `filters.max_bid_price` | 0 | 최저매각가 상한(원). 0이면 비활성 |
| `filters.max_failed_bids` | 1 | 최대 유찰 횟수 (1 = 유찰 2회 미만) |
| `filters.bid_window_days` | 14 | 오늘부터 N일 이내 매각기일 물건만 수집 |
| `filters.regions` | 서울 + 성남·안양·하남·구리·과천·의왕·광명 | `"시도"` 또는 `"시도 시군구"` 접두 매칭. 빈 배열이면 전국 |
| `analyzer.max_analyze_per_run` | 10 | 1회 실행당 최대 분석 건수 (claude 호출 비용/시간 제한) |
| `analyzer.model` | "" | 비우면 claude CLI 기본 모델. 예: `"opus"` |
| `crawler.request_interval_sec` | 1.5 | 법원경매 서버 요청 간격 (줄이면 IP 차단 위험) |

## 상태(status) 의미

| status | 의미 |
|---|---|
| `analyzed` | 권리분석 완료 — 판정(안전/주의/위험)이 대시보드에 표시됨 |
| `pending` | 필터 통과, 분석 대기 (다음 실행에서 분석) |
| `households_unknown` | 세대수 확인 실패 — 네이버 단지 매칭 실패 (대부분 단지명 없는 나홀로 아파트) |
| `excluded_area` | 전용면적 기준 미달 — 대시보드에 표시하지 않음 |
| `excluded_price` | 최저매각가 범위 밖 — 대시보드에 표시하지 않음 |

## 어디서든 보기 — GitHub Pages 배포

`docs/index.html` 은 외부 요청이 없는 단일 파일이라 정적 호스팅에 그대로 올라간다.
GitHub Pages의 `/docs` 소스를 쓴다.

**1) 저장소 생성 후 첫 배포** (github.com 계정 로그인이 먼저 필요하다)

```bash
gh auth login --hostname github.com
```

```bash
cd ~/code/auction-watch && gh repo create auction-watch --public --source=. --remote=origin --push
```

**2) Pages 활성화** — 저장소 Settings → Pages → Source를 `Deploy from a branch`,
Branch를 `main` / 폴더를 `/docs` 로 지정. 1~2분 뒤
`https://<계정>.github.io/auction-watch/` 에서 열린다.

**3) 이후 갱신** — 파이프라인 실행부터 커밋까지 한 번에:

```bash
cd ~/code/auction-watch && ./deploy.sh
```

커밋만 하고 멈추므로 `git push` 로 배포한다. launchd 자동 실행에 물리려면
plist의 실행 명령을 `deploy.sh` 로 바꾸면 된다(push는 여전히 수동).

### 공개 저장소로 운영할 때

이 도구는 법원 공개 자료를 다루지만 그 안에 **개인 실명이 섞여 있다.** 공개
호스팅을 쓸 경우 다음이 적용되는지 확인한다.

| 항목 | 처리 |
|---|---|
| API 키·토큰 | 저장소에 두지 않는다. `config.json` 의 `kapt.service_key` 는 빈 값이고 키는 환경변수로 받는다 |
| `data/` (수집 상태·현황조사 원문·캐시) | `.gitignore` 로 제외 |
| 점유자 이름 | 현황조사서를 읽는 시점에 마스킹 (`홍**` — 성만 남김) |
| 매각물건명세서 비고의 실명 | 법원 비고란에는 유치권 신고인·임차인·소유자 실명이 원문으로 들어온다. `privacy.py` 가 이를 마스킹한다 |
| 물건 주소·사건번호 | 법원이 공개하는 정보라 그대로 게시한다 |
| 검색엔진 색인 | `docs/robots.txt` 로 차단(`Disallow: /`) |

`privacy.py` 의 마스킹은 **텍스트를 훼손하지 않는 쪽으로 보수적으로** 동작한다.
신분 표기와 이름 사이에 공백을 요구하고(`임차인 홍길동` 은 마스킹, `임차인이라면`
은 건드리지 않음) 이름은 3자로 한정한다(`점유자 기재가` 의 '기재' 를 이름으로
오인하지 않도록). 규칙을 손볼 때는 마스킹 대상과 훼손 금지 케이스를 함께
검증해야 한다.

`analyzer.build_input` 단계에서 비고를 먼저 마스킹하므로, 분석 에이전트는
실명을 볼 수 없고 따라서 분석 문장에 실명이 옮겨 담기지 않는다.

> **비공개로 운영하려면** — GitHub Pages 는 private 저장소에서 GitHub Pro(월 $4)가
> 필요하고, 그마저도 **사이트 자체는 공개로 남는다**(URL 을 아는 누구나 열람).
> 사이트까지 비공개로 하려면 **Cloudflare Pages + Access** 가 무료 대안이다 —
> private 저장소를 연결하고 빌드 명령 없이 출력 디렉터리만 `docs` 로 지정한 뒤,
> Zero Trust → Access 에서 열람 가능한 이메일을 지정한다.

### 가격 등 조건 좁히기 — 웹에서 즉시

대시보드 상단 필터 바에서 다시 실행하지 않고 바로 좁힐 수 있다.

- **최저매각가** 하한·상한(억 단위) + 빠른 선택 칩(~5억 / 5~10억 / 10~15억 / 15~20억 / 20억~)
- **전용면적** 하한·상한(㎡), **최소 세대수**, **등급**(S만 / S~A / S~B)
- **정렬** — 종합등급 / 최저가 낮은순·높은순 / 감정가 대비 저렴한순 / 매각기일 임박순 / 세대수 많은순
- 우측에 조건 충족 건수가 실시간 표시되고, `초기화` 로 되돌린다

수집 단계에서 아예 줄이고 싶으면 `config.json` 의 `min_bid_price` / `max_bid_price`
(최저매각가 기준, 원 단위)를 쓴다. 법원 검색 API의 서버측 필터라 수집량 자체가 준다.

```json
"min_bid_price": 500000000,
"max_bid_price": 1500000000
```

상세조회로 최저가가 교정된 뒤에도 범위를 재확인하므로, 유찰로 가격이 내려간
물건이 상한에 걸려 잘못 남는 일은 없다.
| `excluded_households` | 세대수 기준 미달 |
| `error` | 분석 중 오류 — 다음 실행에서 재시도되지 않음 (state.json 에서 해당 항목 삭제 시 재시도) |

같은 물건이라도 **매각기일이 바뀌면**(유찰 후 재매각) 자동으로 재분석한다.
이번 검색에 더 이상 나오지 않는 물건(매각 완료·취하)은 상태에서 정리된다.

## 주의 / 한계

- **비공식 API**: 법원경매정보 사이트 개편 시 엔드포인트/페이로드가 바뀔 수 있다.
  갑자기 `서버 보안정책 차단` 오류가 나면 요청 간격을 늘리고 잠시 후 재시도.
- **권리분석은 1차 스크리닝**: 등기부등본 없이 공개 자료만으로 분석하므로
  "안전" 판정이라도 입찰 전 반드시 등기부등본·현장 확인이 필요하다.
  대시보드 하단에도 동일한 면책 문구가 표시된다.
- **개인정보**: 현황조사서의 점유자 이름과 명세서 비고의 실명은 저장·분석 전
  마스킹(`홍**`)한다.
- **금액 필드 함정**: 검색 목록의 `minmaePrice` 는 유찰 물건에서 감정가와 같은
  값이 오는 경우가 있다. 공고 최저가(`notifyMinmaePrice1`)를 우선 쓰고,
  상세조회의 `fstPbancLwsDspslPrc` 로 최종 교정한다.
- **요청 간격**: 법원 사이트는 IP 단위 차단이 공격적이다(30초에 16회 수준이면
  1시간 차단). `request_interval_sec` 는 2.0초 미만으로 내리지 않는다. 차단
  응답(`data.ipcheck=false`)을 받으면 재시도하지 않고 즉시 멈춘다 — 재시도하면
  차단이 연장된다.
- **`pageSize` 상한은 50**이다. 100 은 서버가 HTTP 400 으로 거절한다.
- **입지 점수는 데이터 연동이 아니다**: AI의 지역 지식 기반 추정치이므로
  참고용이다. 실거래가는 네이버 단지 호가 밴드(전 평형 혼합)로 대체하고 있다 —
  평형별 실거래가가 필요하면 국토부 실거래가 API 키 발급 후 연동 필요.
- 투자·법률·세무 자문이 아니다.
